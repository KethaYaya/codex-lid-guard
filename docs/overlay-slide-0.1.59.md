# Continuous edge-attached slide - 0.1.59

The previous hover animation positioned and resized the native window separately from painting its new image. Even though the calculated panel ended at the screen edge, that split presentation could expose stale pixels while the visible slice grew. Rounded right corners also left transparent pixels beside the display edge.

Hover and click expansion now present each frame's position, visible size, shape, pixels, and opacity together through UpdateLayeredWindow. The message remains 440 DIP wide and uses a one-to-one pixel copy throughout the slide; the window reveals a changing slice rather than stretching the text. Right-attached panels have a flat right edge, including their top and bottom corners. The exposed left corners stay rounded. The stable transparent gutter on the left remains in place to prevent the notch disappearing from moving the panel.

The compositor stays active after expansion, so there is no final switch back to separately resized and painted content. Its image and mask buffers are reserved for the whole slide and reused. Activity ticks modify only indicator pixels in the existing paint buffer, without laying out or redrawing the message text. Mask geometry is cached between identical frames. Hidden windows release the buffers after hiding, and editor activation captures the same currently visible image before its separate restore transition.

Validation passed all 63 overlay checks, including hover reversal, independent tabs, single and double clicks, keyboard routing, busy and completion state, reduced motion, and editor activation success/failure. Clippy passed for all targets with warnings denied. A final targeted editor restore check also passed after moving the compositor reset to occur after hiding the window.

The new native pixel test checks 42 frames at 100%, 150%, and 200% display scaling, including both endpoints and interrupted/reversed motion. It verifies the actual HWND bounds, unchanged source pixel scale across the full visible panel, a filled rightmost pixel column including the corners, and unchanged bitmap handles. Debug-build frame presentation measured 2.325 ms median, 4.743 ms p95, and 5.591 ms maximum. Existing native interaction checks measured hover response at 23.947 ms and tab-click response at 32.466 ms.

The packaged release also completed six independent tab expansions with the first geometry update in 20.286-24.394 ms and median update intervals of 16.286-16.967 ms. Private memory stayed at 5,513,216 bytes and GDI handles stayed at 27. The sampled workload used 8.935% of one CPU core compared with 11.319% for the installed 0.1.58 build; these are single sequential samples with background desktop activity, not a statistical CPU comparison. TypeScript compilation and packaging passed, and all 17 installed extension files were verified against the VSIX (allowing VS Code's added package metadata).

These tests inspect owned native windows, their image pixels, and geometry. They do not measure physical display presentation or guarantee a particular compositor/display frame cadence. Windows continues to control VS Code's own minimize and restore animations.

The implementation follows Microsoft's [UpdateLayeredWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-updatelayeredwindow), [SetLayeredWindowAttributes](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setlayeredwindowattributes), and [CreateDIBSection](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-createdibsection) requirements for atomic layered presentation, mode switching, and GDI synchronization before accessing bitmap memory.
