# Project overlay redesign (0.2.2, slide refinement in 0.2.3, faster timing in 0.2.4)

Builds on the recommended combination in the supplied `overlay-tab-redesign.html`: Tab B (task list) and Drawer A (list with fixed preview). The source artifact's embedded `canvas.json` annotations define the shared status, sorting, path-disambiguation, scrolling, and keyboard-code rules. The subsequent compact-layout request reduces both surfaces and adds coordinated stacking.

- A fixed 152 by 42 DIP tab shows the project name, highest-priority task, status icon, and +N extra-session count. A dot distinguishes unread completions. Since 0.2.5, assigned shortcut codes stay visible beside the count and highlight while the prefix is held.
- The 344 DIP drawer uses up to four 28 DIP rows, a highlighted selection, and a fixed two-line preview/action region below the list. Selecting a row does not move other rows. Mouse-wheel scrolling, scrollbar-track clicks, and thumb dragging handle larger groups without pagination.
- Both surfaces order sessions by needs-response, working, unread completion, then idle/read completion. Selection follows session identity, and equal-priority sessions keep their order.
- Dot, ringed exclamation, and check glyphs share the same status colors. Project stripes turn amber only while a session needs input. Ambiguous folder names get distinct path labels and a path line in the drawer.
- Open and Dismiss act on the selected session. Shortcut letters remain visible whenever shortcuts are enabled. Keyboard Escape dismisses that session; the chevron or existing Tab shortcut folds the drawer.
- A shared layout reserves the drawer height and waits for displaced siblings to finish a 90 ms slide before the 120 ms expansion. Each tab acknowledges its final painted position; intermediate frames never release the opening drawer. Rapid reversals require a fresh acknowledgement. Reduced-motion settings skip the slide but preserve the ordering. Folding keeps that reservation until the last animation frame, then slides neighbors back to their compact slots. Switching projects finishes folding the previous drawer first. Long stacks wrap into adjacent columns. Both top and bottom anchors are supported.
- Expansion explicitly raises its native window without activation. Sibling show/position requests remain below the expanded project, including concurrent slides and tabs returning from a hidden state.

Validation covers stable row geometry, scrolling and drag bounds, priority/selection changes, fixed tab height, collision-free packing and exact slot restoration at multiple display scales, exact open/dismiss targets, same-name projects, native shortcut-code visibility, and native intermediate slide frames, expansion waiting for clearance, return waiting for folding, and non-overlap/slot restoration during click, hover, keyboard, refresh and return paths. Native render fixtures cover 100%, 150%, and 200% scaling, including one session, overflow, shortcut badges, and ten sessions. The native interaction tests use owned test windows and simulated shortcut input, without opening an editor or injecting keyboard input into desktop apps.

The preview command shows five sample sessions across two projects and closes after 35 seconds. The VSIX must be installed and VS Code reloaded to activate the new helper in the extension.
